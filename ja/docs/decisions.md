# 合意済みの判断

## プロダクト

- 初期プラットフォームはYouTubeのみで、配信アーカイブと通常投稿を扱います。
- 対象は同時視聴者数が概ね3～10人の小規模配信者で、最終選択と編集は人が行います。
- 初期学習範囲は直近約50時間と代表動画最大10本です。
- 候補は通常15～120秒で、多次元スコアと総合順位を持ちます。
- フィードバックは◎・○・×と任意の理由タグです。
- 映像分析は音声・文字起こし分析が検証されるまで延期します。

## アーキテクチャ

- Windows 11とRTX 4070 Ti上のローカル環境でDocker Composeを使います。
- FastAPIのAPIと重いWorker処理を分離します。
- PostgreSQL + pgvector、faster-whisper、Ollamaを優先します。
- LLMプロバイダを交換可能にし、動画全編をLLMへ送らず安価な絞り込みを先に行います。
- 別のキュー基盤より先に単純なDBベースのジョブを使います。
- StreamerKnowledgeは証拠付きでバージョン管理します。
- 文字起こしは利用可能な場合CUDAを自動選択し、設定可能なCPUフォールバックを使います。
- Dockerへ渡すローカルメディアは共有`data/`ディレクトリへ置き、大きなメディアをPostgreSQLへ保存しません。
- 後続の決定論的分析で再取得を避けるため正規化音声をローカル成果物として保持し、PostgreSQLにはパスだけを保存します。
- 初期Event検出は、設定可能なRMS音声閾値とバージョン付き日本語文字起こしルールを使い、LLMは使いません。
- EventはClipCandidateと分離した証拠記録であり、同種の近接検出は保存前に統合します。

## 文書

英語をAI向け正本、日本語を同じ構造と意味のオーナーレビュー用ミラーとします。エージェントは`AGENTS.md`、`README.md`、タスクに必要な文書だけを読みます。
