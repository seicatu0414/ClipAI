# アーキテクチャ

## 初期環境

Windows 11、NVIDIA RTX 4070 Ti、Docker Compose、ローカルストレージを使用し、公開デプロイは行いません。

## コンポーネント

- **API（FastAPI）**：チャンネル・動画要求、ジョブ状態、分析結果、フィードバックを扱います。重い処理は実行しません。
- **Worker**：メディア取得、音声抽出、文字起こし、特徴抽出、イベント検出、StreamerKnowledge更新、候補順位付けを行います。
- **Database（PostgreSQL + pgvector）**：メタデータ、履歴、文字起こし、イベント、候補、評価、知識、妥当な場合の埋め込みを保存します。大きな動画・音声はローカルストレージへ置きます。
- **ローカルLLM**：既定候補はOllamaですが、業務ロジックは交換可能なプロバイダインターフェースへ依存します。

パイプラインは、メタデータ解決、メディア取得、FFmpeg正規化、faster-whisper文字起こし、安価な特徴抽出、イベント検出、候補窓統合、関連知識取得、縮小済み候補へのLLM推論、スコアと説明生成、人への提示、フィードバック保存の順です。動画全編をLLMへ送らず、音声・文字起こし・メタデータの安価な信号を先に使います。映像分析は基準線の価値が実証されるまで延期します。

動画プロバイダ、文字起こし、特徴抽出、イベント検出、LLM、埋め込み、候補評価、知識更新は交換可能にします。比較に必要な履歴を上書きせず、パイプライン・モデル・プロンプト・設定を識別可能にします。

初期ジョブ処理はDBベースで十分です。Redis、RabbitMQ、Celery、分散オーケストレーションは根拠が得られるまで導入しません。秘密情報、Cookie、非公開ダウンロード、個人データセットをコミットせず、権限のあるコンテンツだけを分析します。
